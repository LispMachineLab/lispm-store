The catalog of LispM Desktop's App Store: the applications and extensions it offers, with their
icons, and the roles and skills of LispM Agent's agents.  LispM Desktop clones this repository
and reads [[file:catalog.eld][catalog.eld]] as data, never evaluating it: what runs is only the packages you choose to
install, from the package archives or from a git commit the catalog pins.  Every item is
reviewed before it is merged (see [[*Review][Review]]).

* The LispM projects

| [[https://github.com/LispMachineLab/lispm-agent][lispm-agent]]     | AI agents inside Emacs                                            |
| [[https://github.com/LispMachineLab/lispm-desktop][lispm-desktop]]   | Emacs as a Mac OS 9 desktop, set up as a workspace for agents     |
| [[https://github.com/LispMachineLab/lispm-browser][lispm-browser]]   | a WebKit browser in Emacs, with keyboard hints and Chrome extensions |
| *lispm-store*   | the catalog LispM Desktop's App Store installs from (this repository) |

* The catalog

The format below is LispM Desktop's: [[https://github.com/LispMachineLab/lispm-desktop/blob/main/lisp/lispm-desktop-catalog.el][lispm-desktop-catalog.el]] says it for apps and extensions,
and both its App Store and this repository's ~make check~ read the catalog by it.  catalog.eld
holds one property list:

#+begin_src lisp-data
(:name "LispM Store"
 :items
 ((ID :kind KIND :name STRING :description STRING ...)
  ...))
#+end_src

ID is a lower-case symbol unique in the catalog.  Every item has:

| ~:kind~        | ~app~, ~extension~, ~role~ or ~skill~                                             |
| ~:name~        | the name the store shows                                                          |
| ~:description~ | what it is, one line                                                              |
| ~:requires~    | optional: IDs of items to install first, such as the app a skill drives           |

** Applications

An app opens in a window of its own on the desktop, with its own menus in the menu bar.  What it is
called, its subtitle, icon, category, description and needs are said here and nowhere else: the
App Store takes them from the catalog, never from the package.

| ~:subtitle~ | shown under its icon, at most 24 characters                                             |
| ~:category~ | ~news~, ~music~, ~social~, ~productivity~, ~utilities~, ~games~ or ~classic-ai~        |
| ~:icon~     | NAME: [[file:icons/][icons/]]NAME.svg (16 pixels) and icons/NAME-32.svg (32 pixels)                     |
| ~:banner~   | NAME: [[file:banners/][banners/]]NAME.svg, the picture over its page (see [[*The listing][The listing]])            |
| ~:about~    | NAME: [[file:about/][about/]]NAME.md, its introduction, in Markdown                                      |
| ~:author~   | who made what it installs, at most 48 characters                                        |
| ~:license~  | the licence of what it installs, an SPDX expression, as ~GPL-3.0-or-later~              |
| ~:package~  | how to install it, below; absent for a part of Emacs, such as Calc                      |
| ~:command~  | the command that opens it, autoloaded by the package                                   |
| ~:feature~  | instead of ~:command~, for an app running windows of its own: a library that, loaded, says what it does with ~(lispm-desktop-define-app 'ID :activate ... :menus ... :running ...)~, as [[https://github.com/LispMachineLab/lispm-stickies][lispm-stickies]] does, and is unloaded when the app is uninstalled |
| ~:needs~    | optional: programs, libraries and applications it uses beyond Emacs, below             |

~:package~ is a symbol, for a package from GNU ELPA, NonGNU ELPA or MELPA, or
~(PACKAGE :url URL :rev SHA)~ for one from git, at a full 40-character commit SHA (~:lisp-dir DIR~
when its Lisp is in a subdirectory).

#+begin_src lisp-data
(elfeed
 :kind app
 :name "Elfeed"
 :subtitle "Web feeds"
 :category news
 :description "A reader of web feeds, RSS and Atom: ..."
 :icon "elfeed"
 :banner "elfeed"
 :about "elfeed"
 :author "Christopher Wellons"
 :license "Unlicense"
 :package (elfeed :url "https://github.com/skeeto/elfeed"
                  :rev "acbb86e342d2b8f85dfb30dce9df01db9a829c77")
 :command elfeed)
#+end_src

Icons are pixel art in the Platinum style of [[https://github.com/LispMachineLab/lispm-desktop/tree/main/icons/os9][LispM Desktop's own]]: one ~rect~ per run of
same-coloured pixels on a row, ~shape-rendering="crispEdges"~, in Mac OS 9's colours.

*** The listing

Every app and extension gives its whole listing, what its page in the App Store shows: ~:name~,
~:subtitle~, ~:description~, ~:icon~, ~:banner~, ~:about~, ~:author~ and ~:license~, an app its
~:category~ too, and the files they name.  LispM Desktop does not list an item lacking any of it.

- The *banner* is pixel art of 240 by 80 pixels drawn at 480 by 160, as the icons are drawn: it
  starts ~<svg xmlns="http://www.w3.org/2000/svg" width="480" height="160" viewBox="0 0 240 80"
  shape-rendering="crispEdges">~ and holds ~rect~ elements only, at most 120 KB.  It shows the
  app at work, or what it is about, without words: the page shows the name over it.
- The *introduction* is Markdown (CommonMark's core, as [[https://github.com/LispMachineLab/lispm-desktop/blob/main/lisp/lispm-desktop-markdown.el][lispm-desktop-markdown.el]] reads it): no
  first-level heading, as the page shows the name; ~##~ sections; paragraphs, lists, quotes,
  code, ~**strong**~, ~*emphasis*~, ~`code`~ and links to ~https~, ~http~ or ~mailto~ addresses, which the
  page opens; no HTML.  An image alone in its paragraph, ~![words](images/NAME.png)~, shows a
  file of [[file:images/][images/]], never one from the network.  about/NAME.LANGUAGE.md, as about/NAME.fr.md,
  is shown in place of it to those whose LispM speaks that language.

*** Needs

~:needs~ lists entries ~(KIND NAME :for WHAT ...)~, KIND being ~program~ (NAME on ~PATH~),
~library~ or ~application~ (NAME.app):

| ~:brew~      | the Homebrew formula installing it; ~:cask~ for an application                      |
| ~:head~      | ~t~ to install the formula's HEAD, where its release is too old                     |
| ~:xcode~     | ~t~ for a program of Apple's command line tools, as ~git~ or ~swift~                |
| ~:instead~   | programs doing its work while it is missing, as ~afplay~ for ~mpv~                  |
| ~:more~      | what it does that they do not                                                       |
| ~:commands~  | the app's commands needing it, which offer to install it first                      |
| ~:variables~ | the app's options holding it, set again once it is installed                        |
| ~:file~      | a library's file, under its formula's prefix                                        |
| ~:bundle~    | an application's bundle identifier                                                  |

What is missing never blocks installing the app: Get installs it alongside, one install at a time
in LispM Desktop's Installer, with Homebrew.  The catalog names formulas and casks, never commands.

#+begin_src lisp-data
(yeetube
 ...
 :needs ((program "mpv" :for "playing videos" :brew "mpv"
                  :commands (yeetube-play) :variables (yeetube-mpv-program))))
#+end_src

** Extensions

An extension adds to LispM Desktop's editor instead of opening a window, as Hermes adds an agent
beside Claude Code and Codex.  The App Store lists them under Extensions.

| ~:subtitle~ | as an app's                                                                  |
| ~:icon~     | as an app's                                                                  |
| ~:banner~, ~:about~, ~:author~, ~:license~ | as an app's                                   |
| ~:package~  | ~(PACKAGE :url URL :rev SHA)~, from git, pinned as an app's is               |
| ~:feature~  | the library that, loaded, makes it take part; unloaded, it takes part no more |
| ~:program~  | optional: the program it needs on ~PATH~; without it the App Store greys it out |
| ~:install~  | optional: the command installing ~:program~, which the App Store shows        |

#+begin_src lisp-data
(hermes
 :kind extension
 :name "Hermes"
 :subtitle "Nous Research's agent"
 :description "Hermes, Nous Research's agent, in the editor beside Claude Code and Codex: ..."
 :icon "hermes"
 :banner "hermes"
 :about "hermes"
 :author "LispMachineLab"
 :license "AGPL-3.0-or-later"
 :program "hermes"
 :install "curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash"
 :package (lispm-hermes :url "https://github.com/LispMachineLab/lispm-hermes"
                        :rev "aeb7af55924f4e8bb65e8d0df00bc0fbcd38b7c5")
 :feature lispm-hermes)
#+end_src

The library requires LispM Desktop's (~lispm-desktop-ai~ for an agent, calling
~lispm-desktop-agent-define~) and defines ~FEATURE-unload-function~ to undo it; see
[[https://github.com/LispMachineLab/lispm-hermes][lispm-hermes]].

** Roles

Roles and skills are LispM Agent's; the App Store does not list them.  A role is
~:file "roles/ID.org"~:

#+begin_src org
,#+title: Reviewer
,#+description: Reviews changes for bugs and risks; never edits.
,#+tools: (read_file search_files xref_references run_shell send_message)
,#+effort: high

The role's instructions, for the model to read ...
#+end_src

~#+title:~ and ~#+description:~ are required.  ~#+tools:~ is a list of LispM tool names, or ~t~ (the
default) for all.  ~#+effort:~ is ~low~, ~medium~, ~high~, ~xhigh~ or ~max~.  No other keywords: a role
names no backend, model or provider.

** Skills

A skill is ~:file "skills/ID.org"~, or ~"skills/ID/"~ for one with files beside its ~SKILL.org~
(see [[https://github.com/LispMachineLab/lispm-agent#skills][LispM Agent's skills]]):

#+begin_src org
,#+title: Read feeds
,#+description: Search and read the user's web feeds in Elfeed, ...

Instructions, for the model to read ...

,#+begin_src emacs-lisp :lispm load
(require 'elfeed)
(lispm-deftool feeds_search ...)     ; helpers, and tools
,#+end_src
#+end_src

A skill that drives an app ~:requires~ it.

* Listing an item

1. *Write the package*, in a repository of its own: an app's autoloaded command opening its buffer
   (or the ~:feature~ library above), its interface described with ~lispm-desktop-app-ui-define~
   inside ~(with-eval-after-load 'lispm-desktop-app-ui ...)~; see [[https://github.com/LispMachineLab/lispm-desktop#writing-an-application][Writing an application]].
2. *Add one item* to catalog.eld, its package pinned to a full commit SHA, of a release tag where
   there is one, with its whole listing (see [[*The listing][The listing]]): the icons it names in [[file:icons/][icons/]], its
   banner in [[file:banners/][banners/]] and its introduction in [[file:about/][about/]].
3. *Run ~make check~*: apps and extensions by LispM Desktop's rules (an error keeps the item out of
   the App Store, as a listing short of its banner or introduction; a warning leaves it listed, but
   not as it should be; both fail), then this store's: unique IDs, ~:requires~, icons and banners
   drawn as pixel art, the files named and no others, roles' keywords,
   skills' code reads.  Offline; needs lispm-desktop's =lisp/=, beside this checkout or named by
   ~LISPM_DESKTOP~.  In LispM Desktop, =M-x lispm-desktop-store-check-catalog= says the same of any
   catalog.
4. *Run ~make test~*: installs every package as LispM Desktop does and checks that apps' commands
   exist and extensions load, that roles name real tools, and runs the skills' tools.  Needs the
   network and checkouts of lispm-agent and lispm-desktop beside this one (or ~LISPM_AGENT~ and
   ~LISPM_DESKTOP~ naming their =lisp/=).  A new skill adds its test to [[file:test/lispm-store-test.el][test/lispm-store-test.el]].
5. *Open a pull request* adding the item and its files only.  CI runs both checks on Emacs 30.1 and
   31.1, against lispm-desktop's main; it is merged once it keeps the rules below.

* Review

An item is merged when it keeps these rules:

- *The whole listing*: a banner and an introduction of its own, its author and licence as its
  source gives them.
- *Pinned revisions*: a full commit SHA, of a release tag where there is one; updating it is a
  pull request.
- *No build commands*: no ~:make~ or ~:shell-command~; packages install as package.el builds them.
- *No provider names* in roles and skills.
- *Finished assets only*: no drafts, prompts, templates or generation scripts, no unused files.
- *Code read as yours*: an extension's or skill's code runs with everything Emacs can do.  It must
  do what it says and nothing else, its tools must have the right permission class, and changes
  to the user's data must ask first.
- *English*, in every file and commit.
